# 独立审阅与版本交付

适用于动画制作和修订，不要求安装、文档维护或简单打包启动视觉审阅。尊重所在环境的委派权限；工具支持且允许时，默认由一个独立子 agent 审阅，主 agent 制作与修正。使用内部子 agent，不为审阅另建用户任务。不额外调用付费生成服务。

## 版本与上限

- V01 是初版；默认最多三轮修改，依次为 V02、V03、V04。初版不计入修订次数，审阅本身不计一次修订；V04 仍要审阅，但不得未经用户要求继续 V05。
- 每轮只生成一个新候选。V01 无明显问题可直接交付，不为凑足次数制造修改。已到上限、缺少素材或意见无法判断时，保留剩余问题供用户决定，不将其包装成通过。
- 每个已导出的候选进入独立版本目录，不覆盖或删除旧 PNG、GIF、联系表、配置与报告。代码若有共享依赖，保存当时的配置和必要代码快照，避免旧版本无法复现。不得只改标签却覆盖文件。
- 局部修改以已认可版本为基线，写明父版本；V03 不一定必须从 V02 开始。沿用既有编号时从最大编号递增，三轮上限指本次用户请求，不能自行开新批次绕过。

## 主 agent → 审阅子 agent

提供用户原始动作要求、原图、帧数、固定部位、允许的变化、当前版本目录，以及已认可基线（如有）。不要只给精选好看的帧或先告诉审阅者“应该通过”。首次审阅先独立观察；复审先检查新候选，再核查前次问题是否解决和是否出现回归。只加载当前任务相关参考，不复制整段聊天或全部技能资料。

可使用以下委派任务：

> 只读审阅此版本动画，不改动或删除素材。根据原图和用户要求，查看全部帧联系表、关键部位放大图、循环 N-1→N→1→2，以及可访问的 GIF。检查身份和比例、关节连接、遮挡、缺像素、动作语义、手脚节奏及循环。报告实际查看的文件和播放方式，列出可定位问题与不确定项；没有问题就明确说明，不能为修订而编造问题。只返回审阅报告，由主 agent 保存并决定修改。

审阅者不制作替代动画，不修改源文件，不委派更多审阅者。通常复用同一审阅者完成本批次复审；每次必须查看新文件，不能沿用旧结论。

## 反馈与主 agent 决策

每版保存 `review.json`（也可为同等内容的 Markdown）：版本、审阅者身份、实际查看文件、播放方式、问题列表、结论。每条问题包括类别（明确错误／风格建议／不确定）、严重程度、帧号或时间区间、部位、观察证据与建议修正方向。整段节奏问题可注明“全周期”，不要强造精确帧号。

例如：“V01 第 4～6 帧，红腿长度突降，但膝部无对应抬起，观感像伸缩。建议检查投影与膝踝轨迹。”这是反馈格式示例，不是每个角色的预设问题。

主 agent 逐条判断并记录采纳、拒绝或暂缓及理由。先修可证实的结构、完整性和衔接错误；风格建议不自动推翻用户认可的比例或动作。不机械执行反馈，也不能忽略明确错误后声称通过。意见冲突时用原图、帧图和用户要求判断；证据不足则保留不确定状态。

修订后导出新版本，重做相关程序检查和全部帧视觉检查，再交给子 agent 复审。旧版审阅记录不可改成新版结果。

## 能力与诚实边界

- 分别记录 `contact_sheet`、`frame_closeups`、`playback_samples` 或 `continuous_playback` 等实际观察方式。读取 GIF 首帧不是播放；抽样播放截图不是连续观看。
- 无法播放时可审阅静态结构，但时序和自然程度保持未验证。程序零差异、子 agent 同意、预算用完都不能等同于用户认可。
- 没有子 agent 工具或委派权限时，继续有用的自审并标为 `self_review`；不能假扮第二个 agent。子 agent 无法访问素材时先修访问路径；无法解决则记录未完成的独立审阅。
- 独立审阅会增加时间和 token。每轮只用一个审阅者、提供必要素材、聚焦重要问题；无明确可修问题时提前停止。无需为这一流程安装额外软件或改变用户模型设置。

## 最终交付

建议目录为 `V01/`、`V02/` 等，各含 `frames/`、GIF、联系表、运动配置、验证及审阅记录。整组 `result.zip` 包含所有实际产生的版本和 `versions.md`，不包含空版本。不要使用“final”覆盖旧目录。

最终答复依次展示每版编号与 GIF（无法嵌入时提供对应链接），列出本版变化、审阅状态和剩余问题，标记推荐版本；给出每版 PNG 的位置及整组 ZIP。即使某版被否决，也保留并标为“不推荐”，不能悄悄删去。用户以后明确要求清理时再处理。没有完全合格版本时明确说明，推荐只表示当前候选间的选择。

本流程由 agent 编排；现有 CLI 仍只生成单次输出，没有自动创建子 agent、自动多轮修复或汇总所有版本的新命令。
