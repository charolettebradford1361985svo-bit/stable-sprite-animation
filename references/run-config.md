# 运行配置

`prepare` 创建 `run.json`。路径按运行目录解析，不绑定某台电脑。修改控制字段前，查看 `seed-frame.png`：它已经包含留白，不能直接把原图坐标当作帧坐标。

必要字段示例（数值仅说明格式，必须根据实际角色重新选取）：

```json
{
  "schema_version": 1,
  "action": "张嘴后闭嘴",
  "frame_count": 12,
  "columns": 4,
  "rows": 3,
  "frame_size": [128, 128],
  "source_offset": [24, 24],
  "fps": 8,
  "durations_ms": [200,100,100,100,100,80,80,100,100,100,160,240],
  "registration_box": [38, 82, 83, 108],
  "motion_regions": [
    [[51,35],[110,35],[110,82],[70,82],[51,65]]
  ],
  "loop": {"mode": "rest", "rest_frame": 11},
  "seam_probes": [
    {"name": "upper_snout", "box": [82,45,103,59], "max_shift_px": 1.5}
  ],
  "frame_beats": []
}
```

示例不是完整运行目录；保留 `prepare` 自动生成的其他字段。不要靠修改 `frame_size` 或网格字段去补救错误的输入画布。

## 区域与注册

- 所有矩形都是 **`[left, top, right, bottom]`**，不是 x/y/width/height；右下边界不包含在矩形内。
- `motion_regions` 是若干多边形的并集。它必须包含所有预期变化及运动轨迹。例如嘴张开会露出口腔、遮住一部分领口，这些位置也属于运动区。
- 只标需要变动的部分。把全图都标成运动区会使固定像素约束失去意义；把全图都固定则可能得到完全不动的假成功。
- `registration_box` 选固定、可识别、有纹理的部分。头部动作可选衣服/手提箱，手臂动作可选躯干。它不能与运动区相交。空白背景、均匀色块或正在摆动的脚不适合作锚点。
- 注册使用整组共享缩放和各帧平移。它能修整体位置/生成分辨率差别，不能修角色本身的解剖形变。脚本的低分错误应保留给 agent 判断，勿随意降阈值。
- 若循环探针仍检出小幅位移，检查锚点是否过小、纹理重复或仅覆盖脚底；优先换成更有辨识度的稳定区域并在新输出目录重试，不放宽阈值来凑通过。
- 透明边缘直接复用时必须保留 RGBA；不要只比较 RGB 或把原始半透明边缘统一阈值化。生成运动区的 alpha 清理策略由报告记录。

## 循环模式

| 模式 | 用途 | 行为 |
|---|---|---|
| `rest` | 喷嚏、眨眼、张嘴等回到静止的动作 | 查看图集，明确选择 1-based `rest_frame`；首末复用这一生成内姿势，中间帧保持顺序；至少 4 帧 |
| `cycle` | 连续走路、跑步等周期动作 | 保留整组顺序，审查末→首的动作连续性；不要求首末完全相同 |
| `none` | 一次性动作 | 保留顺序，不声称可循环 |

`rest_frame` 不能自动等同于倒数第二帧。应选择眼睛/嘴已恢复、特效消失、与起步姿势兼容的帧。如果没有符合条件的姿势，先修复/重新生成收尾。

`durations_ms` 长度必须等于帧数，单位毫秒，按 GIF 的 10ms 时间精度设置。停顿可以重复画面，但要报告独特画面数。不要为了让报告看起来有 N 个独特帧而人为抖动一像素。

## 循环探针

`seam_probes` 是位置应稳定、内容可匹配的小特征，例如鼻孔、衣领图案、固定配饰。尽量选择位于生成运动区内部、但边界过渡时本来应保持位置的特征：只检查被硬复制的身体会漏掉前脸跳变。

每项给出名字、矩形和允许的最大像素位移。探针不能放在纯色块、即将闭合的眼睛、变化的嘴腔或消散的云上。它不是一般姿势识别器。

- `rest` 必须审查倒数第二帧→末帧、末帧→首帧、首帧→第二帧。
- 如果末尾是连续相同的静止画面，还须审查它前面最后一个不同画面→静止段；开头连续静止时也须审查离开静止段的一步。否则重复静止帧会掩盖真实回位跳变。
- `cycle` 必须审查末帧附近及跨边界的方向和节奏。运动中的特征未必应该零位移，因此视动作选探针、结合逐帧预览解释结果。
- 没有可用探针、纹理不足或相关度低：只能标记未验证，不能推断为无跳变。
- 探针通过仍需视觉检查。固定像素差为零、首尾 hash 相同，都不能单独证明动作质量。

## 输出

`finalize` 输出 PNG 序列、预览 GIF、图集、联系表、来源顺序和 `validation.json`，以及便于交付的 `result.zip`。按报告区分数值检查和视觉检查状态；不要把 `needs_visual_review` 当作“动画已通过”。

保留原始生成图、`run.json` 和提示词在本地运行目录供复现。交付 ZIP 不应夹带 API 密钥、机器绝对路径、缓存或未请求分享的原始图片。
